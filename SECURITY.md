# Security policy

## Vulnerability in Beebreak's code

Report it privately through GitHub: open the repository's **Security** tab,
choose **Report a vulnerability**, and fill in the form. Do not open a public
issue or pull request for a security problem.

Include what you found, how to reproduce it, and which commit or version you
tested. Do not include other people's data.

Handling is best-effort; there is no guaranteed response time.

## Abuse or a data request on a server

The Beebreak project runs no server and holds no user data. Beebreak is
self-hosted: every server has its own operator.

- Abuse by another user, an appeal against a disabled account, or a request to
  export or delete your data: send it to the operator of the server you use.
  The contact address is in that server's privacy notice. The project cannot
  act on a server it does not run.
- A security problem in one operator's deployment (a leaked secret, a
  misconfigured proxy): tell that operator. If the cause is in Beebreak's code,
  also report it as above.

## Operators

Running a server safely is covered in [docs/RUNBOOK.md](docs/RUNBOOK.md),
including "Before you open your server to others".

## Supported versions

The latest tag and `main`. There are no other supported versions.
